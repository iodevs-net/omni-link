# Repository Guidelines

## Project Overview
Omni-Link is a Universal Semantic Intelligence Bridge MCP (Model Context Protocol) server that acts as a proactive semantic intelligence layer for AI agents. It provides a "Spider-Sense" capability to understand code architecture before making changes.

## Architecture & Data Flow
The system follows a three-layer architecture:
- **Layer A (Adaptation)**: Connects to Serena MCP via stdio with automatic reconnection logic
- **Layer B (Compression)**: Filters and prioritizes structural symbols over implementation details using semantic compression
- **Layer C (Interface)**: Exposes simplified MCP tools for rapid consumption by AI agents

Data flows from MCP tool requests → SemanticOrchestrator (routes to Serena or ast-grep based on file type) → Symbol overview/reference retrieval → SemanticCompressor (filters and compresses) → MCP response.

## Key Directories
- `src/`: Main source code
  - `index.ts`: MCP server entry point and tool definitions
  - `lib/`: Core logic modules
    - `orchestrator.ts`: Routes requests to appropriate semantic provider (Serena for TS/JS, ast-grep for others)
    - `compressor.ts`: Implements semantic compression (prioritizes structural lines, removes comments)
    - `serena.ts`: Serena MCP client wrapper
    - `ast-grep.ts`: AstGrep provider for non-TS/JS files
  - `types.ts`: Shared TypeScript interfaces (ISemanticProvider, CallToolResult)
- `build/`: Compiled JavaScript output (generated by `tsc`)
- `docs/`: Documentation (contains auditorias/ subdirectory)
- `.serena/`: Serena agent configuration and state
- `scratch/`: Temporary testing files (e.g., test_mcp.js)

## Development Commands
- `bun install` or `npm install`: Install dependencies
- `npm run build` or `tsc`: Compile TypeScript to JavaScript
- `npm run dev` or `tsc -w`: Watch mode for development
- `npm run start`: Run compiled server (`node build/index.js`)
- `npm run inspector`: Test with MCP inspector (`npx @modelcontextprotocol/inspector build/index.js`)
- Manual test: `node scratch/test_mcp.js` (as mentioned in README)

## Code Conventions & Common Patterns
- **Language**: TypeScript with strict configuration (tsconfig.json)
- **MCP Integration**: Uses `@modelcontextprotocol/sdk` for server implementation
- **Dependency Injection**: SemanticOrchestrator composes SerenaClient and AstGrepProvider
- **Error Handling**: Try/catch in tool handlers with isError flag in responses
- **Async/Await**: Consistent use for all I/O operations (MCP, Serena connections)
- **Semantic Compression**: 
  - Removes comments and empty lines
  - Prioritizes structural keywords (export, class, interface, function, etc.)
  - Truncates to ~2500 characters (~500-600 tokens) with truncation indicator
- **Naming**: CamelCase for variables/functions, PascalCase for classes/interfaces
- **Documentation**: JSDoc-style comments for classes and methods

## Important Files
- `src/index.ts`: Main MCP server implementation exposing three tools:
  - `get_spider_sense`: Returns compressed symbol overview of a path
  - `analyze_impact`: Finds incoming references to a symbol
  - `get_health`: Reports connection health of semantic providers
- `src/types.ts`: Defines ISPsemanticProvider interface and CallToolResult type
- `src/lib/orchestrator.ts`: Core routing logic selecting provider by file extension
- `src/lib/compressor.ts`: Symbol compression algorithm
- `package.json`: Defines dependencies, scripts, and project metadata
- `tsconfig.json`: TypeScript compiler configuration
- `README.md`: Project overview, architecture, and usage instructions

## Runtime/Tooling Preferences
- **Runtime**: Bun or Node.js (both supported)
- **Package Manager**: Bun (preferred) or npm
- **TypeScript**: Version 5.3.3+ (devDependency)
- **Serena Dependency**: Requires `uv` (from astral-sh/uv) to be installed for automatic Serena MCP server launching
- **Node Modules**: ~97 dependencies (mainly @modelcontextprotocol/sdk and zod)
- **Entry Point**: Builds to `build/index.js` executed via Node

## Testing & QA
- No formal test suite found in repository
- Manual verification suggested via:
  - MCP inspector (`npm run inspector`)
  - Scratch test file (`node scratch/test_mcp.js`)
- Testing would focus on:
  - MCP tool request/response validation
  - Serena/ast-grep provider integration
  - Compression accuracy and truncation behavior
  - Error handling and reconnection logic
- Code quality relies on TypeScript compilation and manual review
